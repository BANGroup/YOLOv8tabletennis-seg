### ❌ ЧТО НЕ РАБОТАЕТ:

```python
❌ ПРОБЛЕМА 1: Обратные удары (180°) прерывают розыгрыши
   Причина: max_direction_change = 90°
   Сценарий: Мяч летит вправо, затем влево (смена 180°) → отклонить
   Влияние: КРИТИЧНО - теряются длинные ралли
   Фикс: max_direction_change = 180°

❌ ПРОБЛЕМА 2: Минимальная длительность 1.5 сек слишком высока
   Сценарий: Быстрый пас (0.3-0.5 сек) → отбросить как короткий
   Влияние: КРИТИЧНО - теряются реальные розыгрыши
   Фикс: min_rally_duration = 0.3 сек

❌ ПРОБЛЕМА 3: Нет фильтра ложных детекций
   Сценарий: Шум на 1 кадре → начинает микророзыгрыш
   Влияние: ВЫСОКОЕ - загромождение в логах
   Фикс: Требовать 3+ последовательных детекций

❌ ПРОБЛЕМА 4: Нет проверки минимальной скорости
   Сценарий: Камера трясется на 5 пиксел → начинает розыгрыш
   Влияние: СРЕДНЕЕ - ложные срабатывания
   Фикс: min_velocity = 2.0 пиксель/кадр
```

## 🎬 ПРИМЕРЫ ИГРОВЫХ МОМЕНТОВ И ТЕКУЩИЕ РЕЗУЛЬТАТЫ

### Момент 1: Подача и возврат (2 сек) ✓ РАБОТАЕТ

```
Видео:
├─ 0.0-0.5сек: Подача (мяч летит к сетке)
├─ 0.5-1.0сек: Возврат (мяч летит назад)
├─ 1.0-1.5сек: Новая подача (мяч опять летит)
└─ 1.5-2.0сек: Возврат

Текущая логика:
✓ Начало: 0.0сек (первая подача)
✓ Продолжение: 0.5сек, 1.0сек, 1.5сек (все время на столе)
✓ Конец: При смене на новую подачу (обычно конец)
✓ Результат: 1 розыгрыш, 2 сек ✓ СОХРАНЕН
```

### Момент 2: Быстрый пас (0.4 сек) ❌ ТЕРЯЕТСЯ

```
Видео:
├─ 0.0-0.2сек: Первый удар (мяч летит на стол)
├─ 0.2-0.4сек: Второй удар (противник не достал)

Текущая логика:
✓ Начало: 0.0сек (мяч на столе)
❌ Конец: 0.4сек < 1.5сек → ОТБРОСИТЬ ❌ ПОТЕРЯ
- Результат: 0 сохраненных розыгрышей (ОШИБКА!)
```

### Момент 3: Длинный ралли с обратными ударами (5 сек) ❌ ПРЕРЫВАЕТСЯ

```
Видео:
├─ 0.0-1.0сек: Первый удар (влево: -30°)
├─ 1.0-2.0сек: Возврат (вправо: 150°) → смена 180°
├─ 2.0-3.0сек: Третий удар (влево: -30°) → смена 180°
├─ 3.0-4.0сек: Четвертый удар (вправо: 150°) → смена 180°
└─ 4.0-5.0сек: Пятый удар (влево: -30°)

Текущая логика:
✓ Начало: 0.0сек (мяч на столе)
❌ 1.0-2.0сек: max_direction_change = 90°, но смена = 180°
❌ Отклонить детекцию → розыгрыш прерывается
❌ Результат: Несколько микророзыгрышей вместо одного (ОШИБКА!)
```

### Момент 4: Помеха на 0.1 сек (отскок/сетка) ✓ РАБОТАЕТ

```
Видео:
├─ 0.0-1.0сек: Мяч летит
├─ 1.0-1.1сек: Мяч не видна (отскок или сетка)
├─ 1.1-2.0сек: Мяч вновь видна

Текущая логика:
✓ frames_outside = 10 кадров << 30 кадров (max)
✓ Розыгрыш продолжается ✓ ПРАВИЛЬНО
```

### Момент 5: Ошибка подающего (мяч летит вверх) ⚠️ РАБОТАЕТ, НО МОЖЕТ БЫТЬ ПРОБЛЕМА

```
Видео:
├─ 0.0-0.3сек: Подбрасывание (мяч летит ВВЕРХ)
├─ 0.3-0.6сек: Падение на стол
├─ 0.6-1.0сек: Отскок (мяч не достает сетки)

Текущая логика:
⚠️ Может начать розыгрыш на подбрасывании (0.0сек)
✓ Закончит на 0.1сек вне стола
⚠️ Результат: Микророзыгрыш (потребует фильтра)
```

## 🎯 ОТВЕТЫ НА КЛЮЧЕВЫЕ ВОПРОСЫ

### **Q1: Что считать розыгрышем?**

**Текущее определение:**
```
Розыгрыш = период, когда мяч виден на столе или в движении
           до момента, когда мяч вне стола > 0.5 сек
           И длительность >= 1.5 сек
```

**Рекомендуемое определение:**
```
Розыгрыш = период, когда мяч начинается на столе
           И заканчивается когда мяч вне стола > 0.5 сек
           И длительность >= 0.3 сек (один удар)
           
Это охватит:
✓ Подачу и возврат
✓ Быстрые пассы
✓ Длинные ралли
✓ Почти все реальные сценарии
```

### **Q2: Нужна ли классификация типов?**

**Сейчас:** Нет (все розыгрыши = одного типа)

**Рекомендуется:** Да, для аналитики:
```
- Подача (первый удар с подбрасыванием)
- Возврат (второй удар после подачи)
- Ралли (3+ ударов в обмене)
- Ошибка (мяч не попал на стол)
```

### **Q3: Почему max_direction_change = 90 проблема?**

**Математика:**
```
Мяч летит вправо: угол = -30° (восток-юго-восток)
Игрок отбивает влево: угол = 150° (запад-северо-запад)

Смена угла: |150 - (-30)| = 180°

180° > 90° → ОТКЛОНИТЬ ❌

Это НЕПРАВИЛЬНО! Это нормальный обратный удар.
```

**Решение:** `max_direction_change = 180`
