## Система подсчета очков

### Иерархия подсчета

```
Level 1: IMPACTS (Удары)
   ↓ Каждый раз когда мяч ударяется об стол
   ↓
Level 2: RALLIES (Розыгрыши)
   ↓ Последовательность ударов между игроками
   ↓
Level 3: POINTS (Очки)
   ↓ Результат rally (кто выиграл)
   ↓
Level 4: GAMES (Игры)
   ↓ Первый к 11 очкам (diff ≥ 2)
   ↓
Level 5: MATCH (Матч)
   ↓ Первый к 2 победам в играх
```

### LEVEL 1: IMPACTS (Удары)

**Условия для удара:**
```
1. ✓ Y > height * 0.65      (в зоне стола)
2. ✓ Y движение: вниз→вверх (отскок)
3. ✓ Velocity > 2.0 px/frame (не шум)
4. ✓ Angle > 20-25°          (достаточный перелом)
5. ✓ min_consecutive = 3     (фильтр YOLO шума)
```

**Пример Impact:**
```json
{
  "impact_id": 1,
  "time": 0.3,
  "frame": 18,
  "sender": "Player1",
  "receiver": "Player2",
  "position_x": 300,
  "side": "LEFT"
}
```

### LEVEL 2: RALLIES (Розыгрыши)

**Структура rally:**
```
Rally = Sequence[
  Impact(Player1→Player2),  ← Удар 1
  Impact(Player2→Player1),  ← Удар 2
  Impact(Player1→Player2),  ← Удар 3
  КОНЕЦ (один ошибся)       ← Победитель
]

Rally winner = Тот кто НЕ ошибся
```

**Критерии конца rally:**
- Мяч не вернулся на стол (> 0.5 сек отсутствия)
- Игрок не мог ударить (находится далеко)
- Мяч вышел за границы стола
- Мяч ударил в сетку

### LEVEL 3-5: Points, Games, Match

**Правила:**
- Game: Первый к 11 очкам (diff ≥ 2)
- Match: Первый к 2 победам в играх (best of 3)

## Обнаружение ударов (Impacts)

### Логика определения sender/receiver

**По позиции X (горизонтальная позиция мяча):**

```
ЛЕВАЯ ПОЛОВИНА СТОЛА (X < 960 для 1920x1080):
├─ Кто ударил? → Player1
├─ sender = Player1
├─ receiver = Player2
└─ Мяч летит на Player2

ПРАВАЯ ПОЛОВИНА СТОЛА (X > 960):
├─ Кто ударил? → Player2
├─ sender = Player2
├─ receiver = Player1
└─ Мяч летит на Player1
```

**Чередование ударов:**
```
1️⃣ Player1 ударяет    → sender=P1, receiver=P2
2️⃣ Player2 ударяет    → sender=P2, receiver=P1
3️⃣ Player1 ударяет    → sender=P1, receiver=P2
... и так далее
```

### Критерии удара об стол

```
Удар = True, если ВСЕ условия выполнены:

1. ПОЗИЦИЯ: Y > height * 0.65 (на столе)
   └─ Нижние 35% экрана где находится стол

2. ВЕРТИКАЛЬНАЯ смена направления:
   ├─ Движение ВНИЗ: vy > 0.15
   ├─ Отскок ВВЕРХ: vy < -0.15
   └─ = Перелом траектории = BOUNCE

3. ФИЛЬТР ШУМА:
   ├─ velocity > 2.0 пикс/кадр
   └─ Исключает микрошумы

4. ПЕРЕЛОМ ДОСТАТОЧНЫЙ:
   ├─ angle_change >= 20-25°
   └─ Достаточный угол для валидности

5. ПОСЛЕДОВАТЕЛЬНЫЕ ДЕТЕКЦИИ:
   ├─ min_consecutive = 3 кадра
   └─ Фильтр ложных YOLO детекций
```

### Визуализация события bounce

```
         Мяч летит вниз
              ↓
        ┌─────────────┐
        │   СТОЛ      │  ← Y > height * 0.65
        └─────────────┘
              ↑↑↑
        Мяч отскочил ВВЕРХ
        (BOUNCE DETECTED!)
```

## Анализ Bounce Detection

### Источники информации

**tt_fsm_rules_rev_1.xlsx (главный файл):**
- Contains FSM rules для определения points/games
- Ключевые переменные: bounce_S, bounce_R, net_touch, timeout

**fsm_logic.json (логика):**
```json
{
  "state": "Начало розыгрыша мяча",
  "conditions": {
    "bounce_S": 1,        ← BOUNCE на стороне Sender
    "net_touch": 0,       ← Не коснулась сетка
    "bounce_R": 1,        ← BOUNCE на стороне Receiver
    "timeout": "1"        ← Мяч пропал > 0.5 сек
  },
  "actions": {
    "score_S": 1,         ← Sender получил ТОЧКУ!
    "score_R": 0
  },
  "comment": "Конец розыгрыша"
}
```

### Сценарии FSM для определения points

**Сценарий 1: Player1 ударил, Player2 не смог вернуть**
```
Условие:
- bounce_S = 1 (отскок на стороне Player1)
- bounce_R = 1 (отскок на стороне Player2)
- net_touch = 0 (не сетка)
- timeout = "1" (мяч пропал)

Действие:
- score_S = 1 ← Player1 выигрывает!
- score_R = 0
```

**Сценарий 2: Мяч коснулся сетки**
```
Условие:
- bounce_S = 1
- net_touch = 1 ← СЕТКА!
- bounce_R = 1
- timeout = "1"

Действие:
- score_S = 0
- score_R = 1 ← Player2 выигрывает (Player1 ошибся)
```

**Сценарий 3: Ошибка подачи**
```
Условие:
- bounce_S = 1
- net_touch = 1 ← Коснулось сетки
- bounce_R = 0 ← Не долетело до другой стороны
- timeout = null

Действие:
- score_S = 0
- score_R = 1 ← Player2 выигрывает
```

### ПОЛНАЯ ТАБЛИЦА FSM (10 правил из tt_fsm_rules_rev_1.xlsx)

**ВСЕ КОМБИНАЦИИ УСЛОВИЙ И ДЕЙСТВИЙ:**

| № | Состояние | bounce_S | net_touch | bounce_R | timeout | score_S | score_R | Описание |
|---|-----------|----------|-----------|----------|---------|---------|---------|----------|
| 1 | Начало записи | 0 | 0 | 0 | null | 0 | 0 | Ждем начало розыгрыша |
| 2 | Начало розыгрыша | 1 | 1 | 1 | any | 0 | 0 | Валидная подача (повтор) |
| 3 | Начало розыгрыша | 1 | 1 | 0 | 1 | 0 | 1 | **ОЧКО R** (ошибка подачи) |
| 4 | Начало розыгрыша | 1 | 0 | 1 | null | 0 | 0 | Продолжение розыгрыша |
| 5 | Начало розыгрыша | 1 | 0 | 1 | 1 | 1 | 0 | **ОЧКО S** (R не вернул) |
| 6 | Начало розыгрыша | 1 | 0 | 0 | 1 | 0 | 1 | **ОЧКО R** (S ошибка) |
| 7 | Продолжение розыгрыша | 1 | any | any | any | 1 | 0 | **ОЧКО S** (при продолжении) |
| 8 | Продолжение розыгрыша | 0 | any | 1 | 1 | 1 | 0 | **ОЧКО S** (R ошибка) |
| 9 | Продолжение розыгрыша | 0 | any | 1 | null | 0 | 0 | Продолжение розыгрыша |
| 10 | Продолжение розыгрыша | 0 | any | 0 | 1 | 0 | 1 | **ОЧКО R** (S ошибка) |

**Интерпретация:**
- `any` = значение не важно для этого правила
- `1` = событие произошло
- `0` = событие не произошло
- `null` = не требуется
- **ОЧКО X** = кому начисляется точка

### Логика переходов состояний

```
НАЧАЛО ЗАПИСИ
    ↓ (bounce_S=1 ИЛИ bounce_R=1)
НАЧАЛО РОЗЫГРЫША МЯЧА
    ├─ Если bounce_S=1 AND net_touch=1 AND bounce_R=1 → ПРОДОЛЖЕНИЕ (правило 2)
    ├─ Если bounce_S=1 AND net_touch=1 AND bounce_R=0 AND timeout=1 → ОЧКО R (правило 3)
    ├─ Если bounce_S=1 AND net_touch=0 AND bounce_R=1 AND timeout=null → ПРОДОЛЖЕНИЕ (правило 4)
    ├─ Если bounce_S=1 AND net_touch=0 AND bounce_R=1 AND timeout=1 → ОЧКО S (правило 5)
    ├─ Если bounce_S=1 AND net_touch=0 AND bounce_R=0 AND timeout=1 → ОЧКО R (правило 6)
    │
    └─ ИЛИ ПЕРЕХОД В
    
ПРОДОЛЖЕНИЕ РОЗЫГРЫША
    ├─ Если bounce_S=1 (ANY условия) → ОЧКО S (правило 7)
    ├─ Если bounce_S=0 AND bounce_R=1 AND timeout=1 → ОЧКО S (правило 8)
    ├─ Если bounce_S=0 AND bounce_R=1 AND timeout=null → ПРОДОЛЖЕНИЕ (правило 9)
    └─ Если bounce_S=0 AND bounce_R=0 AND timeout=1 → ОЧКО R (правило 10)
```

### Ключевые выводы из FSM

1. **bounce_S = 1 всегда приводит к ОЧКО S** (правила 5, 6, 7)
   - Это означает: если Sender ударил еще раз → Receiver ошибся

2. **bounce_R = 0 + timeout = 1 → ОЧКО для противника**
   - Если мяч не вернулся на стороне Receiver → Sender выигрывает

3. **net_touch = 1 + bounce_R = 0 → ОЧКО R**
   - Если сетка И мяч не долетел → Sender ошибся

4. **Состояние "Начало розыгрыша"** обрабатывает подачу (6 вариантов)
   - Может быть повтор подачи, или переход в продолжение

5. **Состояние "Продолжение розыгрыша"** обрабатывает обмены (4 варианта)
   - Главное правило: bounce_S=1 → ОЧКО S (противник не вернул)
