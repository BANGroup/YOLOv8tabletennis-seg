                        4 КРИТИЧЕСКИХ ПРОБЛЕМЫ
════════════════════════════════════════════════════════════════════════════════

❌ ПРОБЛЕМА 1: max_direction_change = 90° (ДОЛЖНО БЫТЬ 180°)
   ├─ Сценарий: Обратный удар (180° смена направления)
   ├─ Текущий результат: Отклонить как невалидный ❌
   ├─ Влияние: КРИТИЧНО - Теряются 30-50% длинных ралли
   └─ Сложность фикса: 🟢 Низкая (одна строка)
      Решение: self.max_direction_change = 180  # вместо 90

❌ ПРОБЛЕМА 2: min_rally_duration = 1.5 сек (ДОЛЖНО БЫТЬ 0.3 сек)
   ├─ Сценарий: Быстрый пас (0.3-0.8 сек)
   ├─ Текущий результат: Отбросить как короткий ❌
   ├─ Влияние: КРИТИЧНО - Теряются 40-60% реальных розыгрышей
   └─ Сложность фикса: 🟢 Низкая (две строки)
      Решение: self.min_rally_duration = 0.3  # вместо 1.5

❌ ПРОБЛЕМА 3: Нет фильтра ложных детекций (НУЖНО ДОБАВИТЬ)
   ├─ Сценарий: Шум на 1-2 кадрах создает микророзыгрыш
   ├─ Текущий результат: Начать розыгрыш на каждом кадре
   ├─ Влияние: ВЫСОКОЕ - Загромождение логов, путаница в счете
   └─ Сложность фикса: 🟡 Средняя (20 строк)
      Решение: Требовать 3+ последовательных детекций перед началом

❌ ПРОБЛЕМА 4: Нет проверки min_velocity (НУЖНО ДОБАВИТЬ)
   ├─ Сценарий: Камера трясется на 5 пиксел = ложный розыгрыш
   ├─ Текущий результат: Начать розыгрыш на шумах
   ├─ Влияние: СРЕДНЕЕ - Ложные срабатывания на ненужных кадрах
   └─ Сложность фикса: 🟡 Средняя (15 строк)
      Решение: Требовать min_velocity = 2.0 пиксель/кадр

                        5 РЕАЛЬНЫХ ПРИМЕРОВ ИГРОВЫХ МОМЕНТОВ

МОМЕНТ 1: Подача и возврат (2 сек)
├─ Видео: 0.0-0.5s подача | 0.5-1.0s возврат | 1.0-1.5s подача | 1.5-2.0s возврат
├─ Текущая логика: ✓ РАБОТАЕТ (сохранен 1 розыгрыш)
└─ Вывод: Нормально для этого сценария

МОМЕНТ 2: Быстрый пас (0.4 сек)
├─ Видео: 0.0-0.2s первый удар | 0.2-0.4s второй удар (ошибка)
├─ Текущая логика: ❌ ПОТЕРЯ (0.4 < 1.5, отбросить)
├─ После фикса min_rally=0.3: ✓ СОХРАНЕН 1 розыгрыш
└─ Вывод: КРИТИЧНО исправить

МОМЕНТ 3: Обратный удар (5 сек)
├─ Видео: Обмен ударами туда-сюда (5 раз)
├─ Текущая логика: ❌ ПРЕРВАН (смена 180° при обратном ударе)
├─ После фикса max_dir=180: ✓ СОХРАНЕН 1 ПОЛНЫЙ розыгрыш
└─ Вывод: КРИТИЧНО исправить

МОМЕНТ 4: Отскок от стола (0.1 сек вне видео)
├─ Видео: Мяч летит, отскочил, вновь видна
├─ Текущая логика: ✓ РАБОТАЕТ (продолжает розыгрыш)
└─ Вывод: Нормально, параметр 0.5 сек хороший

МОМЕНТ 5: Ошибка подающего (мяч летит вверх)
├─ Видео: Подбрасывание, падение, не достает сетки
├─ Текущая логика: ⚠️ МОЖЕТ ОШИБИТЬСЯ (может начать на подбрасывании)
├─ После добавления фильтров: ✓ ПРАВИЛЬНО (игнорирует подбрасывание)
└─ Вывод: ВАЖНО добавить проверку направления

❓ Вопрос 1: Что считать розыгрышем для счета?
   ├─ Вариант A: Каждый полный обмен (туда-обратно)
   ├─ Вариант B: Каждый удар отдельно
   └─ Вариант C: Результат (очко заработано)
   
   🎯 РЕКОМЕНДАЦИЯ: Вариант A (каждый обмен)

❓ Вопрос 2: Какая минимальная длительность разумна?
   ├─ 0.3 сек (один удар, fast attack)
   ├─ 0.5 сек (один-два удара)
   └─ 1.5 сек (несколько ударов)
   
   🎯 РЕКОМЕНДАЦИЯ: 0.3 сек (охватит все сценарии)

❓ Вопрос 3: Нужна ли классификация типов ударов?
   ├─ Вариант A: Просто детектировать розыгрыши
   └─ Вариант B: Также классифицировать типы
   
   🎯 РЕКОМЕНДАЦИЯ: ДА (для аналитики)
