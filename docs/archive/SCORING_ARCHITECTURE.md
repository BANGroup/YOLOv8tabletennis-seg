# Архитектура системы подсчета очков в теннисе

**Дата**: 2025-11-07

## 1. Обзор системы

Система подсчета очков состоит из двух основных компонентов:
1. **Rally Detector** - детектирует розыгрыши (rallies) по траектории мяча
2. **Scoring FSM** - Конечный автомат (FSM) для подсчета очков на основе событий в розыгрыше

---

## 2. Компоненты системы

### 2.1 Rally Detector (`rally_detector.py`)

**Задача**: Детектировать начало и конец розыгрыша, определить события

**События (Events):**
- `bounce_S` - отскок мяча со стороны S (Serving)
- `bounce_R` - отскок мяча со стороны R (Receiving)
- `net_touch` - мяч коснулся сетки
- `timeout` - мяч вне стола > 0.5 сек OR смена направления > 180°

**Выходные данные**:
```json
{
  "rally_id": 1,
  "start_frame": 100,
  "end_frame": 500,
  "events": [
    {"frame": 120, "type": "bounce_S"},
    {"frame": 200, "type": "bounce_R"},
    {"frame": 280, "type": "bounce_S"},
    {"frame": 350, "type": "timeout"}
  ],
  "winner": "S" или "R" или null
}
```

### 2.2 Scoring FSM (`scoring_fsm.py`)

**Задача**: На основе событий розыгрыша определить:
- Кто выиграл розыгрыш
- Кому начислить очко (S или R)
- Начислить очко и обновить счет

**Состояния FSM** (из твоей Excel таблицы):

| Состояние | bounce_S | net_touch | bounce_R | timeout | Score_S | Score_R | Описание |
|-----------|----------|-----------|----------|---------|---------|---------|---------|
| Начало розыгрыша | 0 | 0 | 0 | - | 0 | 0 | Ждем события |
| Начало подачи S | 1 | 1 | 1 | any | 0 | 0 | Валидная подача S |
| Начало подачи S | 1 | 1 | 0 | 1 | 0 | 1 | Ошибка подачи S |
| Начало подачи S | 1 | 0 | 1 | - | 0 | 0 | Продолжение розыгрыша |
| Начало подачи S | 1 | 0 | 1 | 1 | 1 | 0 | **Очко S** |
| Начало подачи S | 1 | 0 | 0 | 1 | 0 | 1 | **Очко R** |
| Продолжение розыгрыша | 1 | any | any | any | 1 | 0 | **Очко S** |
| Продолжение розыгрыша | 0 | any | 1 | 1 | 1 | 0 | **Очко S** |
| Продолжение розыгрыша | 0 | any | 1 | - | 0 | 0 | Продолжение розыгрыша |
| Продолжение розыгрыша | 0 | any | 0 | 1 | 0 | 1 | **Очко R** |

## 4. Структура данных

### 4.1 Rally Event
```python
{
    "rally_id": int,           # Номер розыгрыша
    "start_time": float,       # Время начала (сек)
    "end_time": float,         # Время конца (сек)
    "start_frame": int,        # Номер начального кадра
    "end_frame": int,          # Номер конечного кадра
    "events": [                # Список событий в розыгрыше
        {
            "frame": int,
            "time": float,
            "type": str,       # "bounce_S", "bounce_R", "net_touch", "timeout"
            "position": [x, y] # Координаты события

    "winner": str,             # "S" или "R"
    "point_awarded": str,      # Кому дано очко: "S" или "R"

```

## 5. Логика FSM (из Excel)

### 5.1 Переходы состояний

**Правила:**
1. **Начало розыгрыша**: Мяч должен быть на столе + начальные события (bounce_S OR bounce_R)

2. **Валидная подача**:
   - Если bounce_S=1 AND net_touch=1 AND bounce_R=1 → Валидная подача S
   - Если bounce_S=1 AND net_touch=1 AND bounce_R=0 AND timeout=1 → Ошибка подачи S (Очко R)

3. **Продолжение розыгрыша**:
   - Если bounce_S=1 AND net_touch=0 AND bounce_R=1 → Продолжение
   - Если bounce_R=0 AND bounce_S=0 AND timeout=1 → Возможное окончание

4. **Начисление очков**:
   - Очко S: bounce_S=1 AND net_touch=0 AND bounce_R=0 AND timeout=1
   - Очко R: bounce_S=0 AND bounce_R=0 AND timeout=1

### 5.2 Таблица истины

```
bounce_S | net_touch | bounce_R | timeout | Score_S | Score_R | Описание
---------|-----------|----------|---------|---------|---------|--------------------
    0    |     0     |     0     |    -    |    0    |    0    | Начало розыгрыша
    1    |     1     |     1     |   any   |    0    |    0    | Валидная подача S
    1    |     1     |     0     |    1    |    0    |    1    | Ошибка подачи S
    1    |     0     |     1     |    -    |    0    |    0    | Продолжение
    1    |     0     |     1     |    1    |    1    |    0    | Очко S
    1    |     0     |     0     |    1    |    0    |    1    | Очко R
    1    |   any     |   any     |   any   |    1    |    0    | Очко S (продол.)
    0    |   any     |     1     |    1    |    1    |    0    | Очко S (продол.)
    0    |   any     |     1     |    -    |    0    |    0    | Продолжение
    0    |   any     |     0     |    1    |    0    |    1    | Очко R
```

## 6. Принципы SOLID, KISS, DRY в реализации

### 6.1 SOLID

**S - Single Responsibility Principle**
- `RallyDetector` - только детектирование розыгрышей
- `ScoringFSM` - только логика подсчета очков
- `GameStatistics` - только статистика

**O - Open/Closed Principle**
- FSM легко расширяется для новых состояний
- События передаются через JSON без привязки к коду

**L - Liskov Substitution Principle**
- Все события наследуют базовый Event класс
- Все состояния FSM используют единый интерфейс

**I - Interface Segregation Principle**
- `RallyDetector` использует только методы трекинга
- `ScoringFSM` использует только методы FSM

**D - Dependency Inversion Principle**
- Зависимости передаются через конструктор
- FSM не зависит напрямую от конкретной реализации детектора

### 6.2 KISS (Keep It Simple, Stupid)

- Логика FSM в виде простой таблицы (не сложные алгоритмы)
- События передаются в виде простой структуры
- Нет лишней абстракции

### 6.3 DRY (Don't Repeat Yourself)

- Константы (timeout, bounce_types) в отдельном файле `constants.py`
- Методы проверки событий в базовом классе
- JSON схема для валидации данных
