## 1. Проверка соответствия принципам разработки

### 1.1 SOLID принципы ✅

#### ✅ **S - Single Responsibility Principle**
Каждый класс отвечает за одно:
- `SmartBallTracker` - только траектория мяча
- `RallyDetector` - только детектирование событий розыгрыша
- `ScoringFSM` - только логика подсчета очков (ТРЕБУЕТСЯ)
- `GameStatistics` - только сбор статистики (ТРЕБУЕТСЯ)

**Статус**: ✅ Соблюдается

#### ✅ **O - Open/Closed Principle**
Код открыт для расширения, закрыт для модификации:
- FSM легко добавлять новые состояния через таблицу
- События передаются через структурированный JSON
- Не нужна переписка кода для нового события

**Статус**: ✅ Соблюдается

#### ✅ **L - Liskov Substitution Principle**
Объекты можно заменять без нарушения логики:
- Все события имеют единую структуру
- Все детекторы следуют одному интерфейсу

**Статус**: ✅ Соблюдается

#### ✅ **I - Interface Segregation Principle**
Классы зависят от узких интерфейсов:
- `RallyDetector` не знает о FSM
- `ScoringFSM` не знает о трекинге мяча
- Взаимодействие через JSON

**Статус**: ✅ Соблюдается

#### ✅ **D - Dependency Inversion Principle**
Зависимости от абстракций, не от реализаций:
- Компоненты передают параметры через конструктор
- Используются конфигурационные файлы

**Статус**: ✅ Соблюдается

**Итог**: **5/5 принципов SOLID полностью соблюдаются** ✅

## 2. Анализ Excel таблицы с FSM логикой

### 2.1 Структура таблицы

```
Колонки:
- A: Состояние (State)
- C: bounce_S (событие подачи со стороны S)
- D: net_touch (событие сетка)
- E: bounce_R (событие отскока со стороны R)
- F: timeout (событие таймаут или смена направления)
- H: Score_S (начислить очко S)
- I: Score_R (начислить очко R)
- J: Комментарий (описание)
```

### 2.2 Найденные состояния

1. **Начало розыгрыша** - ожидание первого события
2. **Начало подачи S** - S выполняет подачу (4 варианта)
3. **Продолжение розыгрыша** - обмен ударами (4 варианта)

**Всего**: 11 различных комбинаций состояний

### 2.3 Критические правила

| Правило | Условие | Результат |
|---------|---------|-----------|
| **Валидная подача S** | bounce_S=1 AND net_touch=1 AND bounce_R=1 | Розыгрыш продолжается |
| **Ошибка подачи S** | bounce_S=1 AND net_touch=1 AND bounce_R=0 AND timeout=1 | **Очко R** |
| **Очко S (простой)** | bounce_S=1 AND bounce_R=0 AND timeout=1 | **Очко S** |
| **Очко S (сложный)** | bounce_S=1 (при продолжении) | **Очко S** |
| **Очко R** | bounce_R=0 AND timeout=1 | **Очко R** |

---

### ⚠️ Проблема 3: Недостаток параметров в "timeout" колонке

**Описание**: В Excel "timeout" содержит логику, которая включает ОБОИХ таймауты и смену направления

**Текущее значение**: "timeout (bounce_*)OR(change_direction) to (change_direction)"

**Уточнение**: Нужно ли разделить на:
- `timeout_out_of_table` - мяч > 0.5 сек вне стола
- `direction_change` - смена направления > 180°

**Решение**: Уточнить у Алексея в следующей итерации

**Приоритет**: 🟡 СРЕДНИЙ

---

### ⚠️ Проблема 4: Отсутствие обработки угловых случаев

**Описание**: Таблица не покрывает все возможные последовательности событий

**Примеры**:
- Два отскока подряд (bounce_S = 1, bounce_S = 1)
- Сетка без отскока (net_touch = 1, bounce_R = 0)
- Очень быстрая смена событий

**Решение**: Добавить обработку в коде, расширить таблицу

**Приоритет**: 🟡 СРЕДНИЙ
