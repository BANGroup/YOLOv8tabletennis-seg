## 📈 ЛОГИКА ИЗ FSM (КРАТКИЙ ОБЗОР)

### FSM определяет точки (points) так:

```
ЕСЛИ (bounce_S=1 И bounce_R=1 И net_touch=0 И timeout=1)
    ТО score_Sender = 1, score_Receiver = 0

ЕСЛИ (bounce_S=1 И net_touch=1 И bounce_R=0)
    ТО score_Sender = 0, score_Receiver = 1

ЕСЛИ (bounce_S=0 И bounce_R=1 И timeout=1)
    ТО score_Sender = 1, score_Receiver = 0
```

**Главная идея:**
- Сперва определяется ГДЕ произошел bounce (bounce_S или bounce_R)
- ПОТОМ определяется КТО выиграл based на комбинации условий
- FSM обрабатывает все возможные комбинации

## 🔄 ПОЛНАЯ ЦЕПЬ ЗАВИСИМОСТЕЙ

```
Physical Reality (видео матча)
    ↓
YOLO Detection (мяч на кадре)
    ↓
Kalman Filter (сглаживание)
    ↓
Trajectory Tracking (траектория)
    ↓
BOUNCE DETECTION ← ТЕКУЩАЯ ФАЗА!
    ├─ Y-position check
    ├─ Velocity direction check (вниз → вверх)
    ├─ Angle change check
    └─ Consecutive detections check
    ↓
ImpactDetector (обнаруживает bounce)
    ↓
RallyDetector + FSM (собирает rally)
    ├─ Отслеживает bounce_S
    ├─ Отслеживает bounce_R
    ├─ Отслеживает net_touch
    └─ Отслеживает timeout
    ↓
FSM Logic (применяет правила)
    ├─ Применяет условие
    ├─ Определяет who_won
    └─ Выдает score
    ↓
Points/Games/Match (подсчет)
```

**Вывод:** Bounce detection - КРИТИЧНА для всей системы!

### 1. FSM логика - это сердце подсчета очков
```
FSM определяет:
- ЧТО такое bounce в контексте игры
- КТО выигрывает rally
- КАК подсчитываются очки
```

### 2. Bounce detection - критична
```
Без точного bounce detection:
- FSM не будет работать
- Подсчет очков будет неверный
- Все дальнейшие уровни (Points, Games, Match) сломаются
```
