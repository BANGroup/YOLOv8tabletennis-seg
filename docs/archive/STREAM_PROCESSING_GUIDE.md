# Руководство по потоковой обработке видео

**Дата обновления:** 2025-11-08  
**Версия:** 1.0

## Обзор

Потоковая обработка видео через OpenCV позволяет эффективно обрабатывать длинные видеофайлы с минимальными требованиями к памяти. Система включает три основных компонента:

1. **stream_ball_tracker.py** - Базовый потоковый трекер
2. **stream_tracker_advanced.py** - Продвинутый трекер с анализом движения
3. **stream_results_analyzer.py** - Анализатор и визуализация результатов

## Архитектура потоковой обработки

```
Видеофайл
    ↓
Чтение кадров (OpenCV)
    ↓
YOLOv8 обнаружение мяча
    ↓
Анализ траектории
    ↓
Визуализация + Сохранение
    ↓
Выходное видео + JSON данные
```

## Быстрый старт

### 1. Базовая потоковая обработка

```bash
python stream_ball_tracker.py
```

**Параметры:**
- Видео: `GX010138.MP4`
- Модель: `runs/segment/train9/weights/best.pt`
- Результаты: `stream_tracking_results/`

**Что происходит:**
- Читаются кадры потоком
- Каждый кадр проходит обнаружение мяча
- Траектория отслеживается в памяти (макс 50 точек)
- Каждый 5-й кадр сохраняется как изображение
- Выходное видео сохраняется с визуализацией
- Данные сохраняются в JSON

### 2. Продвинутая обработка

```bash
python stream_tracker_advanced.py
```

**Дополнительные возможности:**
- Расчет вектора скорости
- Определение направления движения
- Вывод информационной панели
- Визуализация стрелок скорости
- Расширенная статистика

**Результаты:**
- `stream_advanced_results/tracked_video_advanced.mp4`
- `stream_advanced_results/trajectory_advanced.json`
- `stream_advanced_results/frames/` - Сохраненные кадры

### 3. Анализ результатов

```bash
python stream_results_analyzer.py
```

**Создает:**
- `stream_tracking_report.txt` - Отчет базового трекера
- `stream_advanced_report.txt` - Отчет продвинутого трекера
- Визуализации траектории

## Параметры конфигурации

### Параметры обнаружения

| Параметр | Значение | Описание |
|----------|----------|---------|
| `ball_confidence_threshold` | 0.4-0.5 | Минимальная уверенность для детекции |
| `min_ball_area` | 3-5 | Минимальная площадь маски мяча |
| `max_ball_area` | 5000 | Максимальная площадь маски |

### Параметры траектории

| Параметр | Значение | Описание |
|----------|----------|---------|
| `max_trajectory_points` | 50-80 | Максимум точек в памяти |
| `save_every_n_frames` | 5 | Частота сохранения кадров |

## Производительность

### Требования к ресурсам

- **Память:** 2-4 GB (зависит от размера видео и параметров)
- **GPU:** NVIDIA CUDA (рекомендуется, но не обязательно)
- **Процессор:** Intel i5 / AMD Ryzen 5 или выше
- **Диск:** ~50-100 GB для выходных данных

### Скорость обработки

- **Базовый трекер:** 15-20 FPS (с GPU)
- **Продвинутый трекер:** 12-18 FPS (с GPU)
- **Процессор:** 2-5 FPS (в зависимости от процессора)

### Оптимизация

1. **Использовать GPU:**
   ```python
   model = YOLO(model_path)  # Автоматически использует GPU если доступен
   ```

2. **Уменьшить разрешение входного видео:**
   ```python
   # В коде перед обнаружением:
   resized_frame = cv2.resize(frame, (640, 360))
   ```

3. **Увеличить интервал сохранения кадров:**
   ```python
   save_every_n_frames = 10  # Сохранять каждый 10-й кадр
   ```

## Визуализация

### Информационная панель

На каждом кадре отображается:
- **Время видео** в формате MM:SS.ms
- **Номер кадра**
- **FPS**
- **Количество точек траектории**
- **Разрешение видео**

### Траектория

- **Синяя линия** - путь движения мяча
- **Зеленая точка** - текущее положение мяча
- **Толщина линии** - уменьшается для старых точек

### Направление движения (продвинутый трекер)

- **Оранжевая стрелка** - вектор скорости
- **Текст** - направление (↑, ↓, →, ←, ↗, ↘, ↙, ↖)
- **Скорость** - в пикселях за кадр

## Отладка и решение проблем

### Проблема: Низкий коэффициент детекции

**Решение:**
1. Уменьшить `ball_confidence_threshold` до 0.3-0.4
2. Проверить, что модель правильно обучена
3. Убедиться, что мяч хорошо виден в видео

### Проблема: Невероятная траектория

**Причины:**
- Ложные обнаружения
- Плохая модель

**Решение:**
1. Увеличить `ball_confidence_threshold`
2. Переобучить модель
3. Использовать фильтрацию траектории

### Проблема: Медленная обработка

**Решение:**
1. Использовать GPU
2. Уменьшить разрешение входного видео
3. Увеличить `save_every_n_frames`
4. Уменьшить `max_trajectory_points`
